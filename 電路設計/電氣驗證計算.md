## 1A. ✅ 感測器 5 V 供電（兩板版新增）

MATRIX 的 I²C 埠供電為 **5 V**（使用者實測確認）。兩顆感測器晶片都支援：

| 感測器 | 供電範圍 | 5 V 直接接 |
|---|---|---|
| SCD41 | 2.4 – 5.5 V | ✅ |
| GY-SHT31-D 模組 | 2.4 – 5.5 V，SDA/SCL 內建 10 kΩ 上拉到 VIN | ✅ 不需電平轉換 |

> 《P0接線與驗證指南》原本寫「兩顆感測器都吃 3V3，不要接 5V」——
> **那條規則是為了保護 ESP32-S3**（其 GPIO 不耐 5 V，感測器若在 5 V，
> 模組的上拉電阻會把 I²C 線拉到 5 V 灌進 S3）。感測器本身從來不怕 5 V。
> 拿掉 S3 後此限制自動消失。

**I²C 線長上限**（本架構唯一的新限制）：

```
tr ≈ 0.85 × R × C ≤ 1000 ns（I²C 標準模式上限）

單顆模組上拉 10 kΩ  →  可容忍 118 pF  →  約 1 公尺
兩顆並聯後 ≈ 5 kΩ   →  可容忍 235 pF  →  約 2 公尺
```

感測頭若需離控制盒超過 2 公尺，就得回頭用三板架構讓 ESP32-S3 走 WiFi
（三板韌體已隨 2026-08-07 兩板定案刪除，需要時從 git 歷史取回）。

## 1. 警報線準位（最關鍵）

### 1.1 規格值

| 參數 | 值 | 來源 |
|---|---|---|
| ESP32-S3 輸出高位 V<sub>OH(min)</sub> | 0.8 × V<sub>DD</sub> = 0.8 × 3.3 = **2.64 V** | ESP32-S3 資料表（最壞情況；典型接近 3.3 V） |
| UNO R4 Minima 輸入高位 V<sub>IH(min)</sub> | 0.8 × V<sub>CC</sub> = 0.8 × 5.0 = **4.00 V** | RA4M1，見文末參考 |
| UNO R4 Minima 輸入低位 V<sub>IL(max)</sub> | 0.2 × V<sub>CC</sub> = **1.00 V** | 同上 |

### 1.2 直接相接的計算

```
S3 實際輸出（典型）        3.30 V
R4 判定 HIGH 的最低要求    4.00 V
─────────────────────────────────
餘量                      −0.70 V   ← 負值 = 不合格
（用最壞情況 2.64 V 則餘量 −1.36 V）
```

**判定：❌ 不合格。** 這不是「邊界值、實務上通常會過」，而是**規格上明確不足 0.7 V**。

> **為什麼原指南的說法會失準**：舊款 UNO R3 用 ATmega328P，V<sub>IH</sub> = 0.6 × V<sub>CC</sub> = 3.0 V，
> 3.3 V 有 +0.3 V 餘量所以能動。UNO **R4** 換成 Renesas RA4M1 後門檻提高到 0.8 × V<sub>CC</sub>，
> 同一條線就不再成立。網路上「3.3 V 接 Arduino 沒問題」的經驗多半來自 R3 時代。

### 1.3 ✅ 採用方案：接類比腳 A0，零元件

**跳過「把 3.3 V 抬到 4 V」這個問題，改用不需要 4 V 門檻的輸入。**

R4 的類比輸入量測範圍是 0–5 V（參考電壓 = V<sub>CC</sub>），10-bit 解析度：

```
S3 拉高 3.3 V  →  ADC = 3.3 / 5.0 × 1023 ≈ 675
S3 放開 0.0 V  →  ADC = 0
判定門檻        →  500

HIGH 側餘量 = 675 − 500 = 175 counts（約 0.86 V）   ✅
LOW  側餘量 = 500 − 0   = 500 counts（約 2.44 V）   ✅
```

兩側餘量都很大，不是勉強過關。而且**類比腳本來就吃 0–5 V**，3.3 V 完全在範圍內。

**韌體加軟體遲滯**（取代數位腳才有的施密特輸入，避免雜訊造成抖動）：

```cpp
const int PIN_ALARM_IN = A0;
const int ALARM_HI = 500;   // > 此值判定警報中（約 2.44 V）
const int ALARM_LO = 300;   // < 此值才解除（約 1.47 V）

int alarmRaw = analogRead(PIN_ALARM_IN);
if      (alarmRaw > ALARM_HI) alarmIn = true;
else if (alarmRaw < ALARM_LO) alarmIn = false;
// 介於兩者之間維持原狀 → 遲滯
```

這與同一支韌體裡爐溫聯鎖的 `T_LOCK` / `T_RELEASE` 遲滯是同一個模式，風格一致。

**S3 斷電情境驗證：**
S3 斷電 → GPIO4 高阻抗 → 10 kΩ 下拉把 A0 拉到 **0 V** → ADC 讀 0 < 300
→ 判定無警報 → R4 回 **FALLBACK** ✅ 與《P0接線與驗證指南》§5 第 6 關要求一致。

**安全性不打折**：判斷完全在 R4 內部完成，與 Pi 無關，Pi 當機照樣有效——
「不經 Pi 的硬體旁路」這個設計意圖完整保留。

### 1.4 其他方案比較（為何不採用）

| 方案 | 可行性 | 不採用的理由 |
|---|---|---|
| **A0 類比判位** | ✅ **本案採用** | 零元件、零成本、餘量大 |
| 74**HCT**125／14／04 | ✅ 可行 | 要買料。HCT 是 TTL 輸入準位（V<sub>IH</sub> = 2.0 V）才行；**74HCT14 因有施密特輸入，抗雜訊優於 125** |
| 74**HC**125 | ❌ | V<sub>IH</sub> = 0.7 × V<sub>CC</sub> = 3.5 V，**一樣不夠**。與 HCT 外觀腳位相同，極易買錯 |
| CD4050B | ❌ | 常被推薦，但 5 V 供電下 V<sub>IH</sub> = 0.7 × V<sub>CC</sub> = 3.5 V，同樣不夠 |
| 2N7000 分立式 | ✅ 可行 | 最便宜，但**邏輯反相**，須同步改韌體，多一個出錯機會 |
| BSS138 雙向模組 | ⚠️ **有陷阱** | 見下 |

**BSS138 模組的陷阱**（原指南建議的備案，實際上會害事）：

該模組每通道在 LV 與 HV 兩側各有一顆 10 kΩ 上拉電阻。正常運作時轉換正確，
但在「**S3 斷電**」這個必測情境下：

- S3 斷電 → LV 側電源 0 V → MOSFET 不導通
- HV 側被自己的 10 kΩ 上拉到 **5 V** → R4 讀到 **HIGH**
- 結果：R4 判定「S3 警報中」→ 風扇鎖在 255 全速，**永遠不回 FALLBACK**

這與第 6 關要驗證的降級行為**直接矛盾**，而且會遮蔽 S3 故障（看起來在全力運作，其實感測層已死）。
若加 10 kΩ 下拉去壓制，又會與上拉分壓成 2.5 V，正常運作時反而失效——**兩種情況無法兼顧**。

### 1.5 這個發現的價值

原指南寫「3.3 V 是邊界值，實務上幾乎都過」，該說法來自 UNO **R3** 時代
（ATmega328P，V<sub>IH</sub> = 0.6 × V<sub>CC</sub> = 3.0 V，確實會過）。
換成 R4 的 RA4M1 後門檻升到 4.0 V，同一條線就不成立。

**若沒有事先驗算**，這個錯誤在實機上的症狀會非常難查：S3 明明拉高了、量電壓也有 3.3 V，
R4 就是沒反應——而且它壞的正好是「Pi 當機時保命」的那條路徑，平常測不出來。

## 2. ✅ 下拉電阻選型（10 kΩ，接在 A0 對地）

```
S3 輸出 HIGH 時，流過下拉電阻的電流
  I = 3.3 V / 10 kΩ = 0.33 mA
  ESP32-S3 單腳最大輸出電流 40 mA → 使用率 0.8%           ✅

S3 斷電時，A0 由下拉電阻定在 0 V
  類比輸入漏電流極小（µA 等級），壓降可忽略               ✅ 可靠判定為無警報

ADC 取樣阻抗要求
  建議訊號源阻抗 < 10 kΩ。S3 通電時由推挽輸出驅動（輸出阻抗數十歐姆）→ 遠優於要求 ✅
  S3 斷電時源阻抗 = 10 kΩ（剛好在建議值），但此時讀的是 0 V，充放電無虞          ✅
```

10 kΩ 是合理選擇：再大抗雜訊變差且超出 ADC 建議源阻抗，再小則浪費 S3 的驅動電流。

> ★ **絕不可對 A0 啟用內部上拉**（`INPUT_PULLUP`）：5 V 會經上拉倒灌進不耐 5 V 的 S3 腳位，
> 且讀值完全失真。韌體用 `pinMode(A0, INPUT)`。

## 3. ✅ MOSFET 閘極驅動（R4 D9 → D4184）

- R4 D9 為 5 V 推挽輸出，D4184 模組標示支援 3.3 V／5 V 觸發 → 5 V 驅動綽綽有餘
- PWM 頻率僅數百 Hz～25 kHz，閘極充放電造成的驅動電流與切換損耗在此量級可忽略
- D4184 模組板上通常已含閘極下拉電阻，確保 R4 重置／未初始化時風扇不會誤啟動

> **實測建議**：上電但未執行 `analogWrite` 前，量測 D9 對地電壓應接近 0 V，且風扇不轉。
> 若會誤轉，表示模組無閘極下拉，需自行在閘極對地加 10 kΩ。

## 4. ✅ 風扇電流 vs MOSFET 額定

```
風扇規格          12 V / 0.2 A  →  額定功耗 2.4 W
D4184 模組連續電流 約 15 A（典型模組標稱）
餘量               15 / 0.2 ≈ 75 倍            ✅

啟動突波（無刷風扇內含驅動電路，約 2–3 倍額定）
  ≈ 0.6 A 短暫  →  仍在 15 A 內              ✅
```

**續流二極體**：風扇為無刷式（內部已有換相電路與保護），低側 PWM 斬波通常不需外加。
保險起見可在風扇兩端反並一顆 1N5819（負極環朝 +12 V 側），成本極低。

## 5. ✅ I²C 匯流排（SCD41 0x62 ＋ SHT31 0x44）

```
位址          SCD41 = 0x62，SHT31 = 0x44   →  不衝突              ✅
電源          兩者皆 3.3 V（★不可接 5 V★）                        ✅
上拉電阻      兩片 GY 模組各自板載約 10 kΩ，並聯後 ≈ 5 kΩ
匯流排電容    麵包板短線約 50 pF

上升時間 tr ≈ 0.85 × R × C = 0.85 × 5 kΩ × 50 pF ≈ 210 ns
I²C 標準模式（100 kHz）上限 = 1000 ns
餘量 ≈ 4.7 倍                                                     ✅
```

程式已設 `Wire.setClock(100000)`（標準模式），與上述計算一致。

> 若之後拉長導線（>30 cm）或再掛第三片模組，需重算：每增加一片並聯上拉會讓等效電阻再降，
> 雖然上升時間變快，但總灌電流上升，需確認不超過 3 mA。

## 8. ✅ 12 V 電源預算

```
12 V 變壓器      2 A
風扇             0.2 A
餘量             10 倍                                            ✅
```

**接線鐵則**：12 V 只進 D4184 的 VIN±，**絕不可碰到 3V3／5V 排**。

## 9. ⚠️ 風扇 PWM 頻率（需調參數）

```
R4 analogWrite 預設頻率  約 490 Hz  →  落在人耳可聽範圍，會有嘯叫
建議改用 R4 核心的 pwm.h（PwmOut）拉到 25 kHz  →  高於可聽上限 20 kHz
```

**但有一個取捨要說明**：本案風扇為 **2 線無刷風扇**（XH2.54 兩芯），只能用低側斬波供電。
無刷風扇內部有換相控制電路，供電被斬斷時該電路也跟著斷電：

- 頻率太低（數百 Hz）→ 內部電路反覆重啟，可能出現抖動或轉速不穩
- 頻率太高（25 kHz）→ 內部電容濾波後接近直流，通常較穩，且無嘯叫

因此建議 **25 kHz**。若實測仍不穩，正規解法是換 **4 線 PWM 風扇**（有獨立 PWM 訊號腳，
不斬斷主電源），這也是資料中心風扇的標準做法——可列入之後的改良項目。

另外，無刷風扇有**最低啟動占空比**（常見 30–40%，即 duty ≈ 77–102）：

- 目前 FSM 的 `DUTY = {S0:0, S1:70, S2:220, S3:0}`，**S1 的 70 可能低於啟動門檻而不轉**
- 驗證方式：照《P0接線與驗證指南》§5 第 2 關，用序列指令 `FAN 60`／`FAN 70`／`FAN 80` 逐級測，記下實際最低啟動值
- 若 70 不轉，兩種修法：把 S1 duty 提高到實測值以上，或加入「先給 255 衝 150 ms 再降速」的 kickstart
