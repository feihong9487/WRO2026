## 1. 檔案結構

```
外觀CAD/
├─ params.scad              ★所有尺寸的唯一真相來源★（只有變數，沒有幾何）
├─ common.scad              共用輔助模組（圓角方柱、倒角、柵格、螺柱、定位榫）
├─ parts/                   列印件，一個零件一個檔
│  ├─ base.scad             電子艙底座
│  ├─ chamber.scad          燃燒艙
│  ├─ hood.scad             集煙罩（漏斗：直筒段＋喇叭口）
│  ├─ fan_mount.scad        風扇座
│  └─ sensor_pod.scad       感測器艙
├─ components/              ★外購件★（非列印件，尺寸多為估值）
│  ├─ bowl.scad             金屬爐盆
│  ├─ matrix_r4.scad        MATRIX Mini R4
│  ├─ pi5.scad              Raspberry Pi 5
│  ├─ d4184.scad            D4184 MOSFET 模組
│  ├─ blower_5015.scad      5015 鼓風機
│  ├─ sensors.scad          SCD41 ＋ SHT31
│  ├─ max6675.scad          MAX6675 轉換板 ＋ K 型探頭
│  └─ mist_led.scad         超音波霧化模組 ＋ 罩內 LED 側光
├─ incense_burner.scad      組裝定位 place()、組合件、驗證用模組、輸出分派
├─ 驗證CAD.py               自檢（A–M 共 13 類）
├─ export_step.py           STEP 匯出（給 Onshape）
└─ STEP/                    匯出結果
```

### 相依方向

```
params.scad ← common.scad ← parts 底下的零件檔
            ← components 底下的元件檔
                                     ↘
                                      incense_burner.scad
```

零件檔用 **`use <>`** 引入而不是 `include <>`：`use` 只帶進模組、不執行對方的頂層
敘述，所以零件檔可以自帶一行預覽呼叫（單獨開檔就看得到），又不會污染組合件。

**但 `use` 也不帶變數。** 參數一律寫在 `params.scad`，零件檔裡不要定義數字——
不然 `incense_burner.scad` 看不到它，引用處會算成 `undef`，而幾何是空的時候
交集永遠是 0，**檢查會靜默通過**。（`驗證CAD.py` 現在會擋這種情況。）

### 檔名一律 ASCII

Windows 版 OpenSCAD 的 `include`／`use` 路徑**不吃非 ASCII 字元**：
中文檔名或中文目錄一律回報 `Can't open include file`，而且錯誤訊息本身是 CP950。
註解裡的中文沒問題，只有路徑不行。

## 2. 怎麼開

| 想看什麼 | 怎麼做 |
|---|---|
| 單一零件 | 直接開 `parts/base.scad`（F5 預覽／F6 算繪） |
| 完整組合件 | 開 `incense_burner.scad` |
| 只有列印件（不含外購件） | `-D part="shell"` |
| 爆炸圖 | `-D part="exploded"` |
| 剖半看內部 | `-D SECTION=true`（`SECTION_AXIS` 可選 `"x"` / `"y"`） |
| 列印排版 | `-D part="print_plate"` |
| 單一零件／元件（未定位） | `-D part="solo" -D PAIR_A="pi5"` |
| 單一零件／元件（已定位） | `-D part="placed" -D PAIR_A="pi5"` |

`part` 打錯名字會直接 **assert 失敗**，不會靜默退回組合件。
（原本的預設分支會退回 `assembly()`——那是「算得出東西、但算的是別的東西」，
匯出 STEP 時每個元件都在算整台機器，一個爐盆跑了十幾分鐘才發現。）

**爐面的條紋是預覽假影**，不是模型壞掉：半透明物件在 F5（OpenCSG）不做深度排序。
按 **F6** 就沒有了。要看內部時用 `-D BOWL_ALPHA=0.4`。

## 3. 驗證

```bash
python3 驗證CAD.py          # A–M 全套（會實際呼叫 OpenSCAD 算繪，約 2 分鐘）
python3 ../run_tests.py --scope core    # 跨層規則（核心里程碑）
```

| 代號 | 檢查 |
|---|---|
| A | 語法、模組定義與呼叫 |
| B | 列印規則（壁厚為噴嘴徑整數倍等）＋ **必要參數缺漏** |
| C | 元件裝得下嗎（含感測器艙走線深度） |
| D | 零件放得進列印床 |
| E | 熱設計（空氣間隙、材料） |
| F | 煙道介面一致性 |
| G | 實際算繪：manifold、浮空塊、算繪警告 |
| H | 組裝干涉 ＋ 落座檢查 |
| I | 列印性（懸空面積、橋接跨距） |
| J | 開口外側有沒有被別的零件擋住 |
| K | 與上次的幾何基準比對 |
| L | **開口本身有沒有真的通**（探針貫穿；含「探針自己不能是空的」的前置檢查） |
| M | **外購元件 vs 外殼干涉** |

## 4. 匯出 STEP（給 Onshape）

OpenSCAD **匯不出 STEP**——它是網格／CSG，不是 B-rep。所以走 OCCT 轉檔。

### 4.1 安裝相依（只需一次）

系統 Python 受 PEP 668 保護，**不可用 `--break-system-packages`**（CLAUDE.md §2）。
裝在隔離的 venv 裡：

```bash
cd 外觀CAD
python3 -m venv --without-pip .venv
curl -sS https://bootstrap.pypa.io/get-pip.py | .venv/bin/python
.venv/bin/python -m pip install cadquery-ocp     # 約 300MB
```

### 4.2 匯出

```bash
.venv/bin/python export_step.py                 # 零件 ＋ 元件 ＋ 組合件
.venv/bin/python export_step.py --parts-only    # 只出列印件
.venv/bin/python export_step.py --fn 48         # 改用固定段數
.venv/bin/python export_step.py --fa 3 --fs 0.3 # 更細（檔案更大）
```

輸出到 `STEP/`：每個零件一個檔（列印件 5 ＋ 外購元件 11），
外加 `智慧香爐_組合件.step`。

> ⚠ `STEP/` 目前仍是 2026-08-16 之前的舊匯出（含已移除的理香零件與舊縮口罩），
> 請重跑 `export_step.py` 更新。

### 4.3 這條路做了什麼

```
OpenSCAD 算繪 STL
  → 用共用頂點／共用邊直接建 B-rep 拓樸（不靠縫合容差）
  → ShapeFix_Shape 修
  → ShapeUpgrade_UnifySameDomain 合併共面三角形 → 真正的平面
  → STEPCAFControl_Writer 寫出具名零件與組合件（AP214、單位 mm）
  → ★把 STEP 讀回來驗一次★（體積、實體有效性、零件數）
```

匯出時還會用**散度定理直接從 STL 算一次體積**跟 OCCT 的結果對照——
兩邊差超過 0.01% 就不輸出。這是為了抓「檔案寫得出來、但形狀被動過」的情況。

### 4.4 ★界線：這個 STEP 能做什麼、不能做什麼★

| 能 | 不能 |
|---|---|
| 匯進 Onshape 組裝、量測、做工程圖 | **參數化編輯尺寸** |
| 平面是真正的平面（已合併） | 圓孔／圓柱是**多邊形近似**，不是解析曲面 |
| 零件有中文名稱、組合件有 product 結構 | 沒有特徵樹、沒有草圖 |

**要改尺寸請回頭改 `params.scad` 再重匯。** 在 Onshape 那邊改不會回流到這裡，
而 `params.scad` 才是驗證讀的來源——兩邊分岔的話，驗證仍會說「通過」。

多邊形的邊數由 `--fa`／`--fs`（自適應，預設）或 `--fn`（固定）決定。
預設 `$fa=6 $fs=0.6`：大圓分得細、小孔分得粗。

爐盆是唯一固定細分的東西（`params.scad` 的 `BOWL_FN = 160`），因為預覽時
Ø110 用 48 段看得出稜線——那是「爐面條紋」的成因之一。匯出時腳本會傳
`-D BOWL_FN=0` 把它降回自適應，否則單單一個爐盆就會佔掉幾 MB。

## 5. ★外購元件的尺寸全部是估值★

`components/` 底下**沒有任何一個尺寸實測過**（CLAUDE.md §7）。
它們的用途是干涉檢查與目視確認「裝得下、鎖得到」，
**不可當成實際尺寸寫進報告或簡報**。

| 元件 | 可信度 |
|---|---|
| Raspberry Pi 5 | 板外形 85×56 與孔位是官方公開值；連接器高度是常見規格 |
| 金屬爐盆 | 使用者自備，⌀110×45 是假設值 |
| 5015 鼓風機 | 標稱值放餘量 |
| MATRIX Mini R4 | **官方未公佈外形，整組推估** |
| D4184 / SCD41 / SHT31 / MAX6675 | 常見規格，未實測 |

拿到實體請逐項量過再改 `params.scad`，然後重跑 `驗證CAD.py`——
檢查 M 會告訴你估值不準會不會撞到東西。

## 6. 無明火展示機（2026-08-07）

大會禁明火。查下來的關鍵事實：**整條決策鏈根本不靠煙**——FSM 只看 CO₂ 濃度
與斜率，而 CO₂ 來自人的呼吸。會場圍在攤位前的評審與觀眾**本身就是訊號源**。

沒有火會失去的只有「看得見的煙」，有替代：

| 原本靠火 | 無火替代 |
|---|---|
| 看得見的煙 | 超音波霧化（冷霧，不放 CO₂）＋ 罩內 LED 側光 |

**乾冰不能用**：它是 CO₂ 源，會頂穿 1500ppm 硬警報讓風扇整場全速、分級一次
都展示不出來；而且論述會被自己汙染（量到的是乾冰不是人潮）；冷霧又下沉，
集煙罩抓不到。

### 建置組態

`CAD自檢/mech_params.py` 的 `BUILD_CONFIGS` 定義兩種建置，差別不只尺度，
**還有有沒有明火**。「近爐零件要耐 120°C」在展示機上不成立也不該成立——
那裡沒有 120°C。但廟宇爐的耐熱衝突沒有被藏起來，它會進
`pending_build_conflicts()`，每次跑測試都印出來。

⚠ **冷霧不像熱煙會自然上升**，靠鼓風機抽吸拉進集煙罩。
集煙罩對非浮升煙源抓不抓得到，**只有實體吹過才知道**。

⚠ **任何霧都可能觸發場地的煙霧偵測器**（水霧也不例外，光電式偵測器靠散射光
判定）。這件事只有問主辦單位才知道。

## 7. 已知待處理

- **熱電偶沒有支架。** 交接文件要求探頭懸於爐面上方 2–3cm，
  但目前沒有任何零件提供這個固定方式。`components/max6675.scad` 的探頭
  只是把「應該在哪」畫出來，讓缺少的支架顯眼；它被明確排除在檢查 M 之外
  （見 `驗證CAD.py` 的 `COMP_NO_CHECK`，含排除原因）。
- **外殼層與層之間只有摩擦榫，沒有螺絲。** 底座↔燃燒艙可以加 M4
  （從艙內由上往下鎖，起子搆得到）；燃燒艙↔集煙罩改漏斗大口後
  罩頂開口變寬（內開口 ≈175），起子可及性需重新確認。
- **近爐區實際溫度未實測**，聯鎖門檻 150/130 仍是臨時值。
