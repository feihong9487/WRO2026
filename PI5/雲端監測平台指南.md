# 智慧香爐 — 雲端監測平台建置指南
（Grafana ＋ InfluxDB ＋ Telegraf on Raspberry Pi 5，本地優先、雲端鏡像）

對應交接文件 §2「Pi 5：決策全紀錄、Grafana/Flask 面板」與降級階梯「雲斷 → Pi 本地續跑」。

---

## 0. 架構與選型理由

```
S3 ─MQTT→ mosquitto ─┬→ pi_fsm.py ──→ incense_log_*.jsonl（審計真相來源，可重演）
     （Pi 5 本機）    │        └─MQTT→ incense/decision
                      └→ Telegraf ─→ InfluxDB（本地時序庫）─→ Grafana（:3000 面板）
                             │
                             └（選配）第二輸出 → InfluxDB Cloud（雲端鏡像）
```

- **JSONL 是審計主檔**（決策可重演），**InfluxDB/Grafana 只做視覺化**——兩者職責分離，面板掛了不影響決策與紀錄（模組解耦、可獨立降級）。
- Telegraf 對每個輸出各有 10 萬筆記憶體緩衝：雲端斷線就地緩衝、回線續傳。以 sensor＋decision 各 1 Hz 計，可撐約 13 小時。
- 展場/廟裡沒網路照樣 demo：面板本體在 Pi 上。

## 1. 前置條件

- P0 系統已在跑：mosquitto（已設 `listener 1883 0.0.0.0`，這個設定同時讓 Docker 容器連得進來）、S3 持續發布 `incense/sensor`、pi_fsm.py 正常。
- Pi 可上網（初次拉 Docker 映像需要）。

## 2. pi_fsm.py 的決策發布（已內建，不必再改）

決策紀錄除了寫進 JSONL，也要發布到 MQTT，本地 Telegraf 與上雲橋接才收得到。
`pi_fsm.py` **已內建**這行（2026-07-30 起），在 main() 迴圈裡：

```python
        logf.write(json.dumps(rec, ensure_ascii=False) + "\n")
        client.publish("incense/decision", json.dumps(rec, ensure_ascii=False))
```

> ⚠️ 這行已經在原始碼裡了，**不要再手動加一次**——重複發布會讓資料庫每秒收到兩筆相同紀錄。
> 只需確認它存在即可。

驗證：跑 `python3 pi_fsm.py`，另開一個終端機 `mosquitto_sub -t incense/decision` 應每秒一筆。

## 3. 安裝 Docker 並啟動三件套

```bash
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER
# 重新登入（或 newgrp docker）讓群組生效

mkdir -p ~/incense-cloud && cd ~/incense-cloud
# 把 docker-compose.yml 與 telegraf.conf 放進這個資料夾

docker compose up -d
docker compose ps          # 三個服務都應是 running / healthy
```

確認：

```bash
curl http://localhost:8086/health        # 應回 "pass"
docker compose logs telegraf --tail 20   # 不應有紅色 error
```

預設帳密（**僅限自家區網實驗，正式部署前務必更改**）：

| 服務 | 帳號 | 密碼 / Token |
|---|---|---|
| Grafana :3000 | admin | incense12345 |
| InfluxDB :8086 | incense | incense12345｜Token：`incense-local-token` |

## 4. Grafana 設定（一次性，約 5 分鐘）

1. 瀏覽器開 `http://<Pi的IP>:3000`，登入。
2. 左側 Connections → Data sources → Add data source → **InfluxDB**。
3. 設定：
   - Query language：**Flux**
   - URL：`http://influxdb:8086`（容器互連用服務名稱）
   - Auth 全關
   - Organization：`incense`｜Token：`incense-local-token`｜Default Bucket：`incense`
4. Save & test → 應顯示 datasource is working。
5. Dashboards → New → **Import** → 上傳 `grafana_dashboard_incense.json` → 資料來源選剛建立的 InfluxDB → Import。

## 5. 驗證清單

| 操作 | 面板預期 |
|---|---|
| 系統靜置 | 頂排：狀態=S1 常態（綠）、CO₂ 顯示基線、爐溫≈室溫；曲線每 5 秒左右長一點（SCD41 更新率） |
| 對 SCD41 連續呼氣 | CO₂ 曲線爬升越過 800/900 門檻線；斜率曲線衝過 120 紅線；狀態方塊變 **S2 高峰（橘）**；風扇面板 fan_duty 跳 220、fan_actual 跟上（兩線間距即「<2 s 響應」的視覺證據） |
| 通風靜置 | CO₂ 回落 <800 才退 S1（遲滯不抖動，狀態時間軸看得最清楚） |
| 熱電偶泡熱水 | 爐溫曲線衝過 80 紅線 → 聯鎖方塊變紅、狀態=S3 異常、風扇歸 0 |
| 拔掉 S3 電源 | CO₂ 曲線停止更新（面板誠實反映感測失聯），decision 側持續（Pi 還活著） |

## 6. 遠端存取（「雲端」的三條路）

### 6a. Tailscale（推薦：免費、最快、不開公網）

```bash
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up        # 跳出網址，用 Google 帳號登入即可
tailscale ip -4          # 記下 100.x.x.x
```

手機／筆電也裝 Tailscale、登同一帳號，之後在任何地方開 `http://100.x.x.x:3000` 就是你的面板。免費個人方案即可（額度以官網為準）。要給教練或廟方看，用 Tailscale 的節點分享功能即可，不必給帳號。

### 6b. InfluxDB Cloud 鏡像（真·雲端，零程式碼）

1. 到 influxdata.com 申請 InfluxDB Cloud Serverless 免費帳號，建 bucket `incense`，產生一組 API Token。
2. 打開 `telegraf.conf`，把最下面「雲端鏡像」區塊解除註解，填入你帳號頁面顯示的 URL／Org／Token。
3. `docker compose restart telegraf`。
4. 遠端看資料：本地 Grafana 再加一個指向雲端的 datasource，或直接用 Grafana Cloud 免費層。

**降級階梯演示法**：拔掉 Pi 的網路幾分鐘 → 本地面板照常、雲端曲線暫停 → 插回網路 → 雲端曲線自動補齊（Telegraf 緩衝續傳）。錄下來就是「雲斷 → Pi 續跑」的動態證據。

### 6c. 現成 IoT SaaS（若真的想要帳號式平台）

| 平台 | 型態 | 接入 | 適合 | 主要限制 |
|---|---|---|---|---|
| ThingSpeak | SaaS | HTTP/MQTT | 最快讓「雲端有圖」 | 免費層上傳間隔約 15 秒，面板陽春 |
| Datacake / Ubidots STEM | SaaS | MQTT/API | 拖拉面板、對外分享美觀 | 免費裝置數與資料點有限 |
| Adafruit IO | SaaS | MQTT | 教學範例多 | 免費層頻率與 feed 數受限 |
| Blynk | SaaS＋App | 專屬 SDK | 要手機 App 遙控 | 儀表板客製弱、免費層小 |
| ThingsBoard CE | 開源自架 | MQTT 原生 | 想要裝置管理＋告警推播一站式 | Java＋PostgreSQL，較吃資源、學習曲線陡 |

共通痛點：免費層幾乎都不允許 1 Hz 原始數據，得降頻或只傳每分鐘聚合值。所以主體放本地 Grafana，SaaS 最多當對外展示的鏡像。

## 7. P2 燃燒艙實驗的加值用法

- 每輪實驗的原始曲線都在 InfluxDB 裡：Grafana 面板右上 ⋮ → Inspect → Data → **Download CSV**，直接進試算表／Python 做配對比較、平均±SD、95% CI。
- 建議每輪實驗開始時在終端記下時間戳，事後用 Grafana 時間範圍框選該輪，截圖＋匯出一次完成。

## 8. 安全提醒

- 改掉 compose 檔與本指南中的預設密碼／Token 再對外分享。
- 不要把 3000/8086 埠對公網開放（路由器不要設 port forwarding）——遠端一律走 Tailscale。
- 廟宇實地階段，mosquitto 記得補上帳號密碼（`allow_anonymous false`）。

## 9. 答詢口袋

「面板選型：開源 Grafana＋InfluxDB＋Telegraf，**本地優先、雲端鏡像**。雲端斷線時 Telegraf 就地緩衝、回線自動續傳，Pi 的決策完全不依賴雲——對應降級階梯第一層。JSONL 決策紀錄是審計真相來源，時序資料庫只負責視覺化，兩者解耦、可獨立降級。自建平台不是做不到，是把工程時間留給燃燒艙實測與廟方合作這些只有我們能做的事。」
